# 墨阵 · 守少主

项目的长期目标是：**让玩家通过自然语言创造、修改和组合塔防世界的规则，由受约束的内容格式和确定性 Runtime 执行。** 当前可玩原型叫“墨阵 · 守少主”，采用三国文字合成塔防玩法。

直接用浏览器打开 `index.html`。回归检查：`node test-runtime.js` 与 `node test-demo.js`。

当前“生成战局”和“AI 军师”使用本地关键词匹配与预设模板，尚未接入真实 LLM。已有内容包、有限规则、校验和无头预演，但尚未完成自然语言创作闭环。

## 产品设计主线

玩家的目标体验是：**描述创意 → 查看规则摘要 → 确认应用 → 实战观察 → 继续修改**。保存、分享和复用是长期体验的一部分。

系统按以下边界实现它：

```text
玩家表达意图
    ↓
AI 理解、澄清并生成候选内容
    ↓
结构化内容包 / 受限指令
    ↓
Schema、语义、能力与预算校验 + dry-run
    ↓
玩家确认 → 确定性 Runtime 执行 → 快照和事件 → 表现层
```

AI 提议，Runtime 裁决；战斗 tick 内不调用 AI。新内容优先组合已有能力，无法表达的新机制才由开发者增加原语。

世界模型的八个概念分别是：`Entity`（对象）、`Component`（能力与数据）、`Spatial`（空间）、`Relation`（关系）、`Rule`（触发逻辑）、`Modifier`（数值修正）、`State`（当前状态）、`Presentation`（表现）。它们是长期设计语言，当前原型只实现了其中的一部分。

## 当前原型的玩法

- 馒头随机征兵，费用从 8 起每次增加 2，最高 24；待命区最多 5 张。
- 刀、枪、弓、骑四兵种；同兵种同阶拖放合成，最高五阶。
- 初始开放 6 个阵位，抽到铲子可逐格扩展至 12 格。
- 赵+云、张+飞、黄+忠可以拖到一起，或在同行相邻时自动成将；赵云双目标、张飞范围攻击并击退、黄忠三目标。
- 我方少主初始 6 命；清完一波使敌方少主扣 2 命，默认三阵通关。敌方生命是清波进度，不是另一套对称攻防模拟。
- 击杀返还馒头，非最终波结束奖励 12 馒头；波间可以提交只影响下一波的难度军令。
- 雨天弓兵命中施加 `Frozen`（当前实际效果为减速），枪兵攻击带该状态的目标触发有限链伤；高地使射程增加 20%。

## 设计与实现的差异

以下按 2026-11-07 的仓库代码核对；“已有”仅指当前实现，不代表完整规范通过验收。

| 主题 | 文档设计 | 当前实现 / 待补内容 |
|---|---|---|
| AI 创作 | LLM 生成 JSON、最多 3 轮纠错、摘要确认、再次修改 | 摘要确认与预演已有；生成和军令仍是关键词模板，未接 LLM 和纠错循环 |
| 内容驱动 | 内容包定义塔、怪物、地图和波次 | 怪物、路径和波次读取内容包；单位创建和攻击基础数值仍取 `UNIT_DEFS`，修改包中塔定义尚不能完整改变战斗 |
| 基础玩法 | Demo v0.1 不做升级；精进版一期排除实体合并 | 当前已有升阶、拼字成将、征兵与扩格，属于额外的宿主玩法实现，尚缺对应的正式设计决策记录 |
| 规则系统 | Demo v0.1 整体延后；精进版规划通用有限规则 | 当前已有 `on_hit`、状态、两类效果和高地射程修正，是有限实现；尚无完整选择器、关系、级联队列和运行预算体系 |
| 内容校验 | Schema + 语义 + 能力校验，逐条结构化错误 | 已有部分必填、数值与效果检查；路径、引用、未知字段等未完整覆盖，也没有独立的正式 Schema 文件 |
| 确定性与结算 | 精确生命周期、整数化逻辑、稳定排序、即时死亡确认 | 固定 tick、种子随机和重复运行测试已有；仍使用浮点距离/成长公式，死亡在攻击遍历后统一清理，尚不能视为完整契约已实现 |
| 表现 | Demo 规划像素素材库与 palette swap | 当前为 Canvas 文字单位、程序绘制与 Kenney 命中特效，未实现完整像素素材选配管线 |
| dry-run | Demo 规划无塔与自动布防两种预演；精进版规划预算与详细统计 | 当前只跑固定基础布防，报告胜负、tick、基地生命、金币、击杀与漏怪；不能证明关卡平衡 |
| 版本与回放 | 精确 Runtime 版本、内容哈希、快照恢复和指令回放 | 当前有展示快照和校验和；尚无完整版本绑定、恢复与回放链路 |

另有两处文档细节需在修订基线时处理：Demo §4.6 的路径错误示例中 `[8,1]` 与 `[4,1]` 实际同处一行；精进版 §13 把死亡召唤、条件 Modifier 和预算测试列为进入 P2 前的要求，但这些能力本身安排在 P2。

## 后续设计需要收口的事项

下列是本次梳理后的建议顺序，尚不代表已经作出新的范围决策：

1. **明确宿主玩法定位。** 确认“墨阵”的征兵、合成与拼字成将是否作为正式基础玩法；补齐规则说明及其与 AI 创作的关系。
2. **统一实际可执行的内容契约。** 明确当前支持的字段、数值、效果和限制；使塔定义真正驱动战斗，并补齐结算与校验缺口。
3. **完成最小真实 AI 创作闭环。** 接入 LLM → 校验与纠错 → 预演 → 玩家确认 → 实战 → 再次修改；保留默认关卡回退。
4. **用玩家行为验证。** 沿用 Demo 的 20 条描述测试、最多 3 轮纠错后成功率 ≥80% 的工程目标，以及 3–5 名玩家中多数主动再次创作的产品目标；当前没有这两项的实测记录。
5. **按表达缺口扩展。** 根据真实创作需求增加原语，再评估多路线、召唤、完整羁绊、回放、分享和素材管线。

维护文档时：产品原则归初衷文档，通用概念归平台文档，执行语义归精进设计，当前 Demo 范围与验收归 Demo 文档；README 负责导航、实现状态和差异索引。

## 架构边界

- `runtime.js`：零 DOM / Canvas / 音频依赖的确定性规则层；内容包校验、受限军令、战斗结算和只读展示快照均在这里。
- `app.js`：展示与交互适配层；只启动 `TowerDefenseRuntime.Runtime`，画布根据快照绘制，负责拖放、音效与 UI。
- `test-runtime.js`：无浏览器规则回归；`test-demo.js`：使用模拟 DOM / Canvas 的页面适配与流程回归。

`TowerDefenseRuntime.dryRun(pack)` 可在没有 Canvas、DOM 或音频的情况下跑一局基础布防模拟，返回胜负、tick 数、基地生命、金币、击杀和漏怪指标；后续接入 LLM 时，生成内容必须先经过这一关。

当前首批可组合原语是 `on_hit` 事件、天气状态、`Frozen` 状态、`apply_status`、`chain_damage` 与 `HIGH_GROUND` 空间 Modifier。输入“雨夜/沼泽”会创建雨天内容包：弓兵命中施加 `Frozen` 减速，枪兵攻击带该状态的目标时触发有限次数的链式伤害；高地阵位则由 Runtime 的 `attack_range_milli × 1.2` Modifier 计算最终射程。

## 嵌入 Hikos（space.hikos.cn/arcade/tower-defense/）

游戏作为纯静态站同源托管在 Hikos 的 `/arcade/tower-defense/`，由宿主的 arcade 加载项（`krowworker` 仓 `web/hikos/src/addons/arcade.js`）用 `sandbox="allow-scripts"` 的 iframe 打开；契约是计算图书馆的接入说明 `01_接入说明_1b297d9c`（postMessage v1）。游戏侧实现在 `src/game/hikos.ts`（桥接）与 `src/game/skins.ts`（四款开放城市皮肤的配色）。

- 构建：`VITE_BASE=/arcade/tower-defense/ npm run build`，产物 `dist/`（`index.html` + `assets/` + `BUILD.json`），再由宿主仓 `web/scripts/sync-arcade.sh --from-dir dist` 同步进 `web/arcade/tower-defense/` 随 web 镜像发布。
- 首帧前参数（URL query）：`v=1`、`skin`（如 `union-atlas-3d`）、`accent` / `bg` / `ink`（6 位 hex，去 `#`）、`theme=day|night`、`lang=zh|en`；不认识的皮肤用 `accent/bg/ink` 兜底。
- 运行中消息：游戏 → 宿主 `td:ready {v:1}`（首帧后）、`td:state {state}`、`td:exit`；宿主 → 游戏 `hikos:context`（换皮肤 / 语言 / 明暗，即时生效）、`hikos:visibility`（`false` 时冻结模拟）、`hikos:size`。只认 `event.source === window.parent` 且 `event.origin` 等于自身站点源（联调可用 `?host=http://localhost:端口` 覆盖）。
- 不透明源下没有 localStorage / cookie，状态只在内存；不引外站资源。独立打开（不在 iframe 里）时行为不变，`?palette=default|neon|retro` 选内置配色（旧的 `?theme=<名>` 仍认）。
- 城市皮肤目前只接了**配色**（接入说明 §3.3 的字面量，程序化绘制）；精灵图资产包（任务 435686a6）到位后再接，不要把现在的画面当最终美术。
- 端到端：`tests/e2e/hikos-embed.spec.ts` 用同源宿主模拟页验证握手往返、可见性暂停、语言 / 皮肤切换与退出。

### 世界模式：战场锁在地图的世界坐标上（v0.9.0 起，大厅 #27514）

以前路线、塔位、敌人都是**屏幕坐标**：游戏在透明画布上按百分比排一条折线，再照着宿主报来的朝向 / 缩放去「追」地图，地图一缩放、一转角度，战场就成了盖在上面的固定浮层。v0.9.0 把这件事反过来做，线格式全文见 [`docs/hikos-world-protocol.md`](docs/hikos-world-protocol.md)：

- **路线取自场景的真实街道 / 桥**：宿主在 `hikos:context` / `hikos:map` 的 `map.world` 里给出场景几何（道路中心线、建筑占位、水域，全部是三维世界坐标）。`src/game/worldField.ts` 把道路连成图、在图上寻路（从一栋真实建筑出发，走到母星 / 大本营，不走回头路），塔位排在路边的真实空地上，生成「自由几何」地图（`runtime/types.ts` 的 `MapDef.free`）——模拟直接跑在真实几何上，射程按世界距离算。
- **路面段不出路面**（v0.9.1 起）：路线里标成路面的每一段——包括门口引道拐上路面的那个倒角——都在真实道路的路面内。引道接上窄路（港口栈道宽只有 1）时，倒角在引道那一侧只退到路缘以内 0.05；路够宽的拐角原样不动，塔位的排布也不受这一步影响。
- **跳字和敌人站在同一个高度上**（v0.9.2 起）：宿主回 `hikos:ground` 时可以带上沿路高度剖面（`step` / `profile`：每条路线每隔 0.5 个世界单位一个路面高度，就是它摆敌人用的那一组样点）。游戏照着剖面取路线上任意一处的高度，跳字、命中特效就和敌人同高；以前只有折点高度，折点之间的台阶 / 桥面被一条直线抹平，都会滨水最多差 0.5、哥特教堂最多差 0.88。宿主没给剖面（旧宿主）或剖面对不上路线时，照旧在折点之间插值。
- **同一个相机矩阵**：宿主在渲染每一帧之前把相机的「世界 → 屏幕」矩阵发过来（`hikos:camera`）。战场本体（路线、塔位、塔、敌人、弹道、射程圈、起终点）由宿主按游戏给的 `td:field`（几何，一次）和 `td:frame`（状态，变了才发）画进它自己的三维场景，和地图同一次渲染、有前后遮挡；游戏画布上只剩贴着世界位置的跳字，用同一个矩阵投影。点选塔位也用这个矩阵反算，所以怎么缩放、怎么转，点到的都是地图上那一格。
- **手势交还给地图**：拖动 = 旋转、Shift / 中键拖动 = 平移、滚轮 / 双指 = 缩放、双击空白 = 复位，游戏只把手势原样转给宿主（`td:camera`），由引擎用原生算法去动相机；点一下才是建塔。
- 宿主没给 `map.world`（旧宿主、非三维皮肤）时自动退回原来的屏幕模式，两种模式共用一套规则与内容包。
- 代码：`src/game/worldField.ts`（选路与排塔位，纯函数）、`src/game/worldMode.ts`（相机投影、拾取、`td:field` / `td:frame` 编码，纯函数）、`src/game/main.ts` 的「世界模式」一节（收发、输入、跳字）。
- 测试：`tests/game/worldField.test.ts`、`tests/game/worldMode.test.ts`（四款皮肤的真实几何夹具 `tests/fixtures/world/`，各种缩放 / 方位角 / 俯仰下点选往返、敌人位置还原误差、沿路高度剖面与宿主取高度的算式逐点一致）、`tests/e2e/world-mode.spec.ts`（假宿主按引擎同一套正交相机推矩阵：握手、缩小 / 放大 / 转角度后点选建塔、敌人贴路、带剖面的 `hikos:ground` 回执、手势转发、地图变更重新部署、退回屏幕模式）。联调时加 `?fielddebug`，游戏会把自己算的路线 / 塔位 / 敌人按相机矩阵描在画布上，与宿主画的三维战场应当重合。

## 军师（LLM 顾问）

军师是玩家的参谋，不是裁判：每个建造期给两三条有取舍的路（各自一张小卡，点一下采纳），波内每 4 s 一条即时指令，外加三样玩法：**战前押注**（军师押这波漏几只，打完结算，战绩「你 n : m 军师」常驻）、**波间变招**（接下「人海 / 急行 / 硬骨头」之一换下波更狠、现在拿加成金）、**复仇一局**（战局结束后把战报喂给关卡军师，出一张针对弱点的关）。军师说的话只是建议：采纳只产出 `build` 命令，走 `sim.ts` 里与玩家点击完全相同的校验；校验链与规格见 `06_军师规格`（任务 3a53bf89 → fb4d93bc）。

- 代码：`src/advisor/`（`types.ts` 契约与 zod 形状、`snapshot.ts` 最小决策快照、`session.ts` 请求生命周期与校验链、`local.ts` 本地模板兜底、`prompt.ts` 提示词、`channels.ts` 三种通道、`select.ts` 选通道），`src/game/advisorCard.ts`（HUD 卡片与棋盘叠层），`src/runtime/gambit.ts`（变招是规则层的一部分，进校验和）。
- 通道（`?advisor=`）：`local` 本地模板（零网络，确定性）；`host` 嵌入时经 Hikos 宿主代理（`td:advisor:request` / `hikos:advisor:reply`，宿主只补凭据与 `response_format`，提示词与快照由游戏出）；`http://…` 或 `/path` 是 HTTP 开发代理。缺省：嵌入 → host，独立 → local；嵌入时禁止游戏直连 HTTP。宿主 `hikos:context.advisor {enabled, provider}` 说没配 → 不等截止直接本地。
- 开发代理：`tools/advisor-proxy.cjs` 是 OpenAI 兼容上游的翻译层，凭据只从运行代理的进程环境读（`ADVISOR_UPSTREAM_URL` / `ADVISOR_API_KEY` / `ADVISOR_MODEL`，可选 `ADVISOR_AUTH_HEADER` / `ADVISOR_JSON_MODE=off`），游戏包里没有任何端点或密钥。`npm run advisor:proxy` 起在 8787，然后开 `http://localhost:5173/?advisor=http://localhost:8787/advisor`。
- 兜底与门槛：截止 下一波 6 s / 即时 2.5 s / 关卡 20 s；超时 · 断网 · 不成形 · 没有可用选项 → 本地模板上墙并亮「本地模板 · 原因」徽记；即时指令超时或过期（快照老于 60 tick）→ 丢弃一条「军师迟到」；战局已变 → 作废；迟到 / 重复回包 → 丢弃。快照里没有坐标、路径、皮肤、种子或任何用户信息（`FORBIDDEN_KEYS` 在测试里逐键断言）。
